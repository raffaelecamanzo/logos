3. WHAT THIS BASELINE IS NOT — the index generation
---------------------------------------------------

The store was cold-indexed on 2026-09-08 with logos 1.4.7, BEFORE S-374 merged.
Refusal rows are written at INDEX time, so this store holds none of S-374's ~115
HTTP client-call refusal rows.

So this artifact is a post-change PAYLOAD SHAPE over a pre-S-374 INDEX GENERATION,
and it says so in its own `generation` block. Quoting it as a post-S-374
measurement would attribute the later rise in the invocation unbound column to the
wrong cause — which is precisely the failure mode CR-120 exists to remove.

CR-120's acceptance criterion is therefore CONDITIONALLY MET by this artifact: the
baseline is measured, durable, labelled and reconciled, and the one thing it cannot
carry is a figure that only a re-index of the 84-member workspace can produce. That
re-index is a human-gated sprint-review step, not a session step. Section 5 is the
procedure that closes it in one operation.

5. THE REFRESH PROCEDURE (the human-gated re-index)
---------------------------------------------------

At the sprint-review human gate, on a binary built from this sprint's merged main:

  1. `logos init --workspace --yes` at ~/source/pec-services. This re-enrols the
     root and spawns the detached warm supervisor that indexes the 84 members
     (~43 s to return). A root `logos index` covers the ROOT ONLY — 3 files — and
     that is correct, not a failure.
  2. Wait for `.logos.workspace.warm.json` to report every member warm.
  3. Re-run this harness against the refreshed store:

         LOGOS_REF_WORKSPACE=~/source/pec-services LOGOS_BASELINE_WRITE=1 \
           cargo test -p logos-core --test coverage_headline_baseline -- --nocapture

     which rewrites the `measurement` block of the JSON beside this file.
  4. Update the `generation` block: `contains_s374_refusal_rows` becomes true and
     `index_built_by` / `index_built_on` become the refreshed binary and date.
  5. Restate the `deltas` entries whose status is `pending-reindex` as `observed`,
     with the figures the run produced, and update section 4 of this file.
  6. Commit both files.

The figures the refresh would change are exactly those enumerated under S-374 in
section 4. If any OTHER figure moves, that is a finding in its own right and the
remedy is to record it — never to bend the classifier back to the numbers here.
