--------------------------------------

Its 55 rows are NOT the ~115 HTTP client-call refusals S-374 added. Read that
carefully, because the two are easy to conflate and the difference is a fact
about the corpus, not about the classifier:

  54  broker `topic-not-literal` refusals  — the header-form publish sites
      CR-117 / S-370 made visible.

      `no-provider-in-workspace`, not `unbound`. CR-120 CRA-02 calls it
      "unbound" colloquially, but here `unbound` is a term of art that excludes
      that bucket (ADR-53), so the two readings differ by one row.

  A direct census of all 84 member stores agrees, cell for cell:
  `http-client-call 1`, `broker-publish 54`, `broker-subscribe 16`,
  `grpc-call 0`. The 16 subscribes key successfully, so they index providers and

S-374's HTTP refusal rows are absent because they are written at INDEX time and
this store was cold-indexed on 2026-09-08 with 1.4.7 — before S-374 merged.
Re-indexing the reference workspace is a human-gated sprint-review step in this
sprint's risk register, so this harness deliberately does not do it. Expect the
invocation `unbound` column to rise by roughly 115 production rows (131
workspace-wide, main + test) on the first re-index that carries S-374; the
`bound` column is not expected to move, because a refusal never binds.

That is the number the split now makes legible and no earlier payload could:
the invocation population's bound half is zero, and it is zero next to an
81-row headline.


IS THE FIGURE AUDITABLE?
------------------------

Yes, and the harness asserts it rather than claiming it. Two properties are
asserted on every run of this harness:

  * the split recomputes from the rows' own `intake` — 874 contract-surface +
    55 invocation = 929 references, matching the per-population totals above;
  * the two populations sum to the four headline counters.

Both are properties of the code rather than of the corpus, so they hold for any
workspace — but read that precisely: they are asserted only WHEN THIS HARNESS
RUNS, which needs a corpus. Corpus-free, the same two properties are guarded by
`federation::coverage::tests::the_classification_counts_split_by_intake_and_sum_to_the_headline`.

The 81/0 pair is a property of THIS corpus at THIS commit, and it is asserted:
a moved corpus FAILS this harness deliberately. The failure message prints the
measured value and says to RECORD the new figure here — never to bend the
classifier to reproduce this one.
