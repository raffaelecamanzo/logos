  With the fork in the provider index the same template is served by TWO
  directories — `archive-api` and `archive-api-logiclens-fork`, the duplicate —
  so path-only matching refuses it as ambiguous and S-411's path-only set never
  held these pairs. Take the fork out of the identity registry and out of the
  provider index together, as CR-158 section 3.2 A requires, and the exactly-one
  rule reaches `archive-api` on path alone: the coupling is one the invocation
  intake already reports. The fork was the only reason these two pairs ever
  looked addressed-but-unresolved.

  So S-475's sensitivity ("STRICT would read 13") was the registry change WITHOUT
  the fork-free subtraction, and its caveat was the decisive one. The run
  reproduces that sensitivity exactly — under S-411's path-only set the
  members-only registry adds precisely these two pairs, asserted — and then the
  fork-free subtraction takes both back.
